# Go Conventions

## Tech Stack
Go 1.27 · Gin · PostgreSQL 15 · `lib/pq` (raw SQL, no ORM) · `golang-migrate` · `golang-jwt/jwt/v5` · Zap · Testify · Mockery v2 · `shopspring/decimal` · `google/uuid` · `oklog/ulid/v2` · AWS SDK v2 (SQS) · `prometheus/client_golang` · `swaggo/gin-swagger`.

## ID Types
- `google/uuid` — `work`, `supply`, and reservation ids.
- ULID strings — `service_order_id` values, received from the Service Order service (`oklog/ulid/v2` `NewULID` exists in `internal/pkg/id` for generators; the catalog itself only stores what it receives).

## Monetary Values
Always use `shopspring/decimal.Decimal`, never `float64` or `float32`. DB column type: `NUMERIC(10,2)`. Responses serialize money as strings with two decimals.

## No Framework Leakage
- Domain packages: zero imports from `gin`, `lib/pq`, or any `repository`/`controller` package.
- Services: only domain interfaces, DTOs (`adapters`), `uow` and `db` packages. No SQL.
- Gin types are confined to `internal/app/` (routing, middleware, responses).

## Mock Generation
Mocks are generated by Mockery from `//go:generate` directives on the interface files:
```go
//go:generate go run github.com/vektra/mockery/v2@latest --name=SupplyRepository --with-expecter
```
Current generated mocks (excluded from the coverage gate):
- `internal/supply/interfaces/mocks/` — `SupplyRepository`, `SupplyService`
- `internal/work/interfaces/mocks/` — `WorkRepository`, `WorkService`
- `internal/pkg/uow/mocks/` — `Executor`

Run `make mockgen` to regenerate. Never edit generated mock files manually. A mock is only generated for an interface that a test uses; do not keep mocks nothing imports.

## Error Patterns
- Domain errors: `var ErrXxx = errors.New("...")` in each domain's `domain/` package (`work_errors.go`, `supply_errors.go`, `errors.go`).
- Services return domain errors; `internal/pkg/web` maps them to HTTP codes (`web.Error`), with allow-lists per status.
- Never expose internal error details in HTTP responses. Infrastructure errors are logged in full and answered with a generic message.

## In-Memory Implementations
Each domain repository has a `*_in_memory.go` (or `in_memory.go`) next to its Postgres implementation in `repository/`. It is used exclusively by unit tests.

## Configuration
All env vars are read with `internal/pkg/env` (`GetString`, `GetInt`, `GetTimeDuration`). Current keys:

| Key | Default | Used by |
|---|---|---|
| `PORT` | `8082` | HTTP server |
| `POSTGRES_HOST` / `_PORT` / `_USER` / `_PASSWORD` / `_DB` / `_SSLMODE` | `5432` / … | `internal/app/db.go` |
| `JWT_SECRET` | `your_jwt_secret` (dev only) | JWT validation |
| `INTERNAL_TOKEN` | empty (fail closed) | `/internal/*` guard |
| `SEED_ENABLED` | off | seed of the fixed works and supplies |
| `CATALOG_QUEUE_URL` | empty (consumer off) | SQS consumer |
| `AWS_REGION`, `AWS_ENDPOINT_URL` | — | SQS client |
| `LOG_LEVEL` | `INFO` | logger |
| `SERVICE_NAME` | `catalog-service` | logger field |

The Makefile reads `.env` and exports it automatically.
